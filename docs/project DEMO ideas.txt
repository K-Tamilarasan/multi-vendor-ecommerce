🔐 Important security point

Right now serializers expose:

'user'
'cart'
'wishlist'

That's okay for our initial serializer layer.

But later our API must enforce:

Logged-in Customer
       ↓
Only their own
       ↓
Address / Cart / Wishlist

Otherwise one user could potentially try another user's ID.

We'll solve that with authentication + permissions + queryset filtering, not by trusting React.

இது mainly:

Email + Password
      ↓
JWT Serializer
      ↓
Access Token + Refresh Token

Example response concept:

{
    "access": "...",
    "refresh": "..."
}
